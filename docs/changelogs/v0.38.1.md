# v0.38.1 — `scipio-code` tool calls written as text are run instead of shown

_2026-10-11_

Non-breaking. No config or deploy changes. Only affects web search with
`scipio-code`, or any other model built on `qwen3-coder`.

## Fixed

### `scipio-code` sometimes wrote its tool call as text

The symptom, in a session with web search on:

```
I'll try to access the website you mentioned using the fetch_page tool.

<function=fetch_page> <parameter=url> https://www.kraken.com </parameter> </function> </tool_call>
```

No page was read, and the raw markup ended up in the reply.

`qwen3-coder` writes tool calls as
`<tool_call><function=…><parameter=…>…</parameter></function></tool_call>`.
`scipio-code` has the same `PARSER qwen3-coder` as its base model, and
Ollama's parser only recognizes a call that opens with `<tool_call>`. The
model sometimes leaves that tag out. Ollama then returns the call as plain
content with no `tool_calls`, and Scipio UI treated it as the final answer.

Reproduced on 2026-10-11 against the Scipio mini: the same request sent
three times to `scipio-code` gave two proper tool calls and one call
written as text without the opening tag. The site wasn't the cause:
`https://www.kraken.com` returns `200 text/html`, so the page read would
have worked.

`recoverTextToolCalls` in `src/lib/webSearch.ts` now handles it. When a
request offered tools and the reply has no tool calls, it looks for
`<function=…>…</function>` blocks, with or without the `<tool_call>` tags,
naming `web_search` or `fetch_page`. It reads their `<parameter=…>` values
and runs them as real tool calls, then removes the markup from the reply.
Any text around the markup ("I'll fetch the page.") stays, shown above the
step. The next request sends the call back to the model as a proper
assistant `tool_calls` message.

Markup naming any other function is left alone, and nothing is recovered
when web search is off. So a coding answer that shows this syntax is
untouched.

## Tests

2 new tests in `tests/web-search.test.ts`:

- `recovers a tool call the model wrote as text`: replays the exact text
  `scipio-code` produced. The page is fetched once, the markup is gone from
  the chat, and the next request carries the call as `tool_calls`.
- `leaves tool markup alone when web search is off`: the same markup in a
  normal reply is shown as written, with no tool run.

All 120 Playwright tests pass with 2 workers. Type check and lint are clean.

## Deploying

On the mini:

```bash
~/scipio-ui/deploy/update.sh
```

Nothing in `deploy/` changed, so the install scripts don't need to run
again. The sidebar shows `v0.38.1` after a reload.

## Known

- **The markup can flash while the model is writing.** Replies stream as
  they're generated, so the text is visible until the reply finishes, then
  it's replaced by the "Read: …" step.
- **`scipio-think` isn't covered.** It writes tool calls in a different
  format (JSON inside `<tool_call>`) and wasn't seen dropping its tags. If
  it does, the same recovery can be extended to that format.
- **A deliberate example can be run.** With web search on, a reply
  containing a `<function=web_search>` or `<function=fetch_page>` block is
  treated as a call, even if the model meant to show the syntax.
- **Changelog file names.** This file follows Warden's `vX.Y.Z.md`
  naming; `0.37.1.md` and `0.38.0.md` predate it.
