# v1.0.0 — Attach files, and let the model run Python in your browser

_2026-10-12_

Non-breaking. No config or deploy changes; nothing new runs on the Scipio
mini. Existing sessions work as before. Both new features are off until you
use them, and Python only works with models that support tools
(`scipio-think` and `scipio-code` both do).

1.0.0 marks Scipio LLM as complete for day-to-day use on the Scipio mini:
the preset server, web search through SearXNG, file uploads and Python.

## Added

### File uploads

A paperclip button in the prompt bar attaches files to your next message:
text, code, CSV/TSV, JSON, Markdown, logs and PDFs, up to 25MB each.

- The model gets each file's text in the conversation, inside
  `<FILE name="…" size="…">` tags, as its own user message before your
  prompt. Files show as a chip in the chat with their name and size.
- **Large files are trimmed** to the first 12,000 characters (about 3K
  tokens of the 16K context). The chip then reads "the model sees the
  start; Python reads all of it", and the model is told the file was cut.
- **PDFs** are converted to text in the browser with pdf.js, page by page.
  pdf.js only loads when a PDF is attached.
- **Refused, with a message:** files that aren't text (checked from the
  content, not only the extension) and PDFs with no text, such as scans.
- **Where files are kept:** the original goes into the browser's IndexedDB
  (`scipio-files`), not localStorage, which only holds about 5–10MB.
  Deleting the attachment or its session deletes the file. Files are only
  ever sent to the mini, as text.

### Python (`run_python`)

A terminal button next to the web search globe lets the model run Python.
It's set per session and turns orange when on.

- **Runs in your browser,** with [Pyodide](https://pyodide.org) 314.0.7
  (Python 3.14), in a Web Worker so the page stays responsive. Nothing runs
  on the mini.
- **Libraries:** numpy, pandas, scipy, statsmodels, scikit-learn, sympy and
  matplotlib, loaded the first time code imports them.
- **Uploaded files** are available at `/data/<name>`, so the model can work
  on a whole CSV and only read back the results. That gets around the 16K
  context limit for data.
- **Variables persist** between runs in a session.
- **In the chat,** each run is a step, "Ran Python (N lines)" or
  "Python error (N lines)". Expanding it shows the code and output, and
  matplotlib charts appear under it. The model sees printed output, the
  last line's value and any error, up to about 4,000 characters, but not
  the charts.
- **Limits:** 5 runs per answer, and 2 minutes per run, including the first
  run's download. A run that times out or is stopped with the Stop button
  ends the worker: Python restarts and earlier variables are gone.

### Tools work together

Web search and Python can both be on. The model then gets both sets of
tools, and an answer can take up to 10 model turns (it was 8). Tool calls
`scipio-code` writes as text (see v0.38.1) are recovered for `run_python`
too, with the code's indentation kept.

## Security

Code the model writes may have been steered by a web page it read, and from
your browser it could otherwise reach the mini and the VPN. For example,
Ollama accepts requests from any page, including ones that delete models.
So the Python worker has no network access, apart from Pyodide's own
downloads from `cdn.jsdelivr.net/pyodide/`:

- `fetch` and `XMLHttpRequest.open` are replaced in place and locked, so
  they can't be restored through prototypes. A test confirms
  `WorkerGlobalScope.prototype.fetch` is blocked too.
- `WebSocket`, `WebSocketStream`, `WebTransport`, `EventSource`, `caches`
  and `Worker` are removed.

## Changed

- Tool handling moved to `src/lib/tools.ts`. `webSearch.ts` only handles
  `web_search` and `fetch_page`, and the new `python.ts` and
  `pythonWorker.ts` handle `run_python`.
- `pyodide` (for types and offline tests) and `pdfjs-dist` 6.3.289 are new
  dependencies.

## Tests

10 new tests in `tests/files-and-python.test.ts`. The Python tests serve
Pyodide from `node_modules/pyodide` instead of the CDN, so they run offline.

Files (4):

- A Markdown file reaches the model as a `<FILE>` user message before the
  prompt.
- A 3,000-row CSV is trimmed to 12,000 characters, with the note.
- A generated one-page PDF is read as text.
- A binary file is refused with a message.

Python (6):

- The toggle offers `run_python` and explains it in the system prompt.
- Code runs, output reaches the model, variables persist, and no
  package-loading messages leak into the output. The expanded step shows
  code and output.
- A script reads an uploaded CSV from `/data`.
- A `ZeroDivisionError` reaches the model, and the step reads "Python
  error".
- `fetch`, the prototype `fetch` and `XMLHttpRequest` are all blocked, and
  `WebSocket` is gone.
- Stopping a `while True` loop restarts Python, and the next run works.

All 130 Playwright tests pass with 2 workers. Type check and lint are clean.

Also checked live against the mini: `scipio-think`, with real Pyodide and
pandas, analysed an uploaded 400-row fills CSV. It hit a `NameError`
(forgot `import numpy`), fixed it on the next run, and reported slippage of
1.89, 2.96 and 4.78 bps for Kraken, Bybit and Coinbase, matching the
values calculated separately. 1.8 minutes in total.

## Deploying

On the mini:

```bash
~/scipio-ui/deploy/update.sh
```

Nothing in `deploy/` changed. The sidebar shows `v1.0.0` after a reload.
The browser needs internet access to reach `cdn.jsdelivr.net` the first time
Python runs; the mini doesn't.

## Known

- **A dynamic `import()` can still send a GET** from the Python worker. It
  can't send a body, pick a method, or read a cross-origin response.
- **Files stay in the browser they were uploaded in.** Another browser or
  device shows the chip and the trimmed text, but Python can't open the
  original there.
- **Only the start of a large file reaches the model** without Python. Turn
  Python on for anything that needs the whole file.
- **Excel files aren't supported.** Save them as CSV first.
- **Charts are saved with the session** in localStorage. Many charts in one
  session can fill it; the app warns when it's full.
- **`scipio-think` still sees `/think` added to each message** until its
  template is fixed on the mini. That's a model change, not part of this
  release.
